# Arqis 0.1.0 — Front End

Status: Planned

## Goal

Deliver a usable compiler front end for a small C-like language. The `arqis` executable should
process a source file, build and validate its AST, and report useful diagnostics, but does not yet
need to produce a native user executable. The v0.1 syntax contract is `docs/grammar.md`.

## Scope sources

Each feature below is in scope if and only if its plan document in `plans/` is marked
"Planned for 0.1.0". Plan documents marked "Deferred", "Unscheduled", or "Rejected" are out of
scope for this release even when their syntax is reserved in the grammar.

## In scope

### Language features

- lexical structure: line and block comments, identifiers, keywords, operators, and sigils
- numeric literals: integer and floating-point forms, base prefixes, contextual typing,
  representability checks (`plans/literals.md`)
- strings and character literals: immutable null-terminated `const char*` literals, one-byte
  character literals with contextual `u8` representation (`plans/strings.md`)
- type system: primitives (`int`, `float`, `char`, `bool`, `void`), explicit-width integers
  (`iN`/`uN`), `usize`/`isize`, pointers, `null`, fixed arrays `T[N]`, raw pointers `T[]`, VLAs,
  `const` qualification, transparent type aliases, `sizeof`/`alignof` (`plans/type-system.md`)
- structs and methods: fields, member functions, receiver rules, explicit pointers,
  C-style aggregate initialization, no implicit copy/move (`plans/structs-and-methods.md`)
- enums: nominal variants, variant access, no implicit integer conversion, exhaustive-or-default
  switch (`plans/enums.md`)
- unions: C-style overlapping storage, C-style construction, incomplete declarations, no implicit
  copy/move, no runtime tag (`plans/unions.md`)
- function pointers and callback types: C-style declarator syntax, `&function` and bare-name
  decay, exact signatures (`plans/function-types.md`)
- scopes and declarations: lexical block scopes, shadowing, single declaration space, explicit
  variable types, function prototypes/forward declarations, incomplete struct/union declarations
  (`plans/scopes-and-declarations.md`)
- import declaration syntax without cross-file resolution; `static` module-private visibility
  (`plans/modules.md`)
- control flow: `if`/`else`, `while`, `do`/`while`, `for`, `switch` statements with C-style
  fallthrough, `break`, `continue`, `return`, exhaustive-return analysis
  (`plans/core-semantics.md`)
- switch expressions: value-producing with implicit arm values; no fallthrough; initial patterns
  are literals, enum variants, and `default` (`plans/pattern-matching.md`)
- `defer`: LIFO execution, call-only form, evaluation/capture at registration time
  (`plans/defer.md`)
- expressions: left-to-right evaluation order, C-aligned precedence, unary/pointer operators,
  pointer arithmetic, raw indexing, assignment, compound assignment, `?:`, comma operator,
  aggregate initialization, comparisons (`plans/core-semantics.md`)
- runtime memory model semantics: fail-fast allocation, `free(null)` no-op, `realloc` behavior
  (`plans/memory-model.md`)
- compiler diagnostics: severity policy, source spans, error recovery, reserved-feature and
  reserved-keyword messages (`plans/diagnostics.md`)

### Implementation work

- lexer and token model
- complete AST model
- parser and syntax diagnostics
- semantic analysis and type checking
- command-line interface (`arqis check`, `arqis dump-ast`, `arqis help`, `arqis version`)
  (`plans/cli.md`)
- parser, semantic-analysis, and diagnostic tests

## Explicitly out of scope

- cross-file module resolution, visibility enforcement, and project entry points (0.2.0)
- native executable generation, IR, and codegen (0.2.0)
- decorators (`plans/decorators.md` — unscheduled)
- custom `comptime` execution (`plans/comptime.md` — unscheduled)
- generics (`plans/generics.md` — unscheduled)
- Arqis build scripts (`plans/build-scripts.md` — unscheduled)
- standard-library split and external dependencies (`plans/stdlib-split.md` — unscheduled)
- distinct types (`plans/distinct-types.md` — unscheduled)
- C ABI and embeddability (`plans/abi.md` — deferred)
- bit-fields (`plans/bit-fields.md` — deferred)
- error-handling constructs such as `Result`/exceptions (`plans/error-handling.md` — rejected for
  the initial language)
- string interpolation
- struct templates
- advanced standard-library containers
- variadic functions, closures and captured environments, reference types
- `goto` and user-defined labels
- undefined-behavior hardening and memory-safety guarantees beyond the documented model
- optimization beyond what is required for correctness

## Acceptance criteria

The release is complete when valid single-file programs can be lexed, parsed, and semantically
validated, and invalid programs produce useful diagnostics. The compiler must expose a front-end
command such as `arqis check source.qis`; native executable generation is deferred to 0.2.0.

The minimum command-line interface is:

```text
arqis check source.qis       # lex, parse, and validate
arqis dump-ast source.qis    # print the formatted AST for debugging
arqis help
arqis version
```

Commands take an explicit source path. The compiler does not implicitly read `main.qis`.

Every grammar rule in `docs/grammar.md` must have parser coverage.

Syntax reserved for planned features is diagnosed explicitly when encountered in 0.1. Reserved
keywords and sigils are not treated as ordinary identifiers; the compiler reports that the feature
is unavailable in this release rather than silently accepting a different meaning.
